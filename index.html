HOW BUILDS ARE CALCULATED
Data Source
All data comes from the OpenDota public API (api.opendota.com), specifically the /api/scenarios/itemTimings endpoint. This endpoint aggregates item purchase data from public parsed matches over the past ~30 days. Only matches that have been fully parsed by OpenDota's replay parser are included.
Each record in the raw data represents a unique item + time bucket combination, with a count of how many times that item was purchased at that timing, and how many of those games were won.
MMR Bracket Filter
Selecting a bracket passes a rank_tier parameter (1–8) to the API, where 1 = Herald and 8 = Immortal. If multiple brackets are selected, a separate request is made for each and the results are merged by summing game counts. If no bracket is selected, data across all skill levels is returned.
Note: The rank_tier filter on this endpoint reflects the average rank tier of all 10 players in the match, not the individual player's rank. High-bracket players playing with lower-bracket friends may appear in lower tiers.
Game Phases
The API records item purchases at fixed time snapshots (in seconds). These are grouped into four phases:
PhaseTime WindowAPI BucketsTypical Items
Starting Items≤ 10 min450 s, 600 sTangos, Clarity, Wraith Band, Null Talisman
Early Game10 – 15 min720 s, 900 sBoots, Magic Wand, Bracer
Core Items15 – 25 min1200 s, 1500 sBKB, Battlefury, Aghanim's
Late Game25+ min1800 sButterfly, Heart, Satanic
Duplicate merging: Items that appear at multiple time buckets within the same phase are merged — game counts are summed and the earliest timing badge is shown.

Mutually exclusive items: Items that no player would buy twice in one game (e.g. two different sets of boots) are grouped. Within each phase of each build card, only the top-ranked item from each group is shown.
The Three Builds
Items are ranked independently within each game phase — they are not extracted from single complete games. Each build shows the top items for that phase according to a different ranking strategy:
BuildRanking LogicBest For
POPULAR Sorted by game count — items purchased most often Seeing what the majority of players actually buy
OPTIMAL Sorted by win rate (wins ÷ games) Items statistically correlated with winning, regardless of pick rate
BALANCED Sorted by score = win rate × log₁₀(games + 10) Items that are both popular and high-win-rate — avoids obscure items with inflated win rates from tiny sample sizes
Win Rate Displayed on Each Card
The percentage shown top-right on each build card is the weighted average win rate across all items in the Early, Core, and Late phases (Starting Items are excluded as they are purchased in every game regardless of outcome). It is calculated as: total wins across all shown items ÷ total games across all shown items. This is a rough indicator — since items are independent, it does not represent the win rate of playing the full build exactly.
Green = above 53%  ·  Gold = 47–53%  ·  Red = below 47%
Lane Filter
When a specific lane is selected (Safe, Mid, Off, or Jungle), the analysis switches from the item timings endpoint to the OpenDota Explorer — a SQL interface that queries individual parsed matches filtered by lane_role.
Because lane-filtered data uses individual match records rather than pre-aggregated API data, the items shown are end-of-game inventories rather than purchase timings. No phase breakdown is available in this mode.
Data caveat: The OpenDota Explorer draws primarily from Captain's Mode (professional / practice lobbies). Standard ranked game modes (All Pick, Turbo, Single Draft, etc.) make up only a small fraction of the parsed dataset, so game mode filtering is not supported in lane-filtered builds.
Time Window Fallback
Lane-filtered queries default to the past 30 days. If fewer than 20 distinct item combinations are found — which can happen for less-played heroes or narrow bracket + lane combinations — the tool automatically widens the window to 90 days, then to all available data, stopping as soon as enough combinations are found.
The time window used is always shown in the metadata bar below the panel header.
Item Slot Reduction
End-of-game builds normally show all 6 item slots. When the sample size is small, 6-slot combinations are too specific to accumulate enough games — so the tool progressively drops the least globally popular item from each combination until a grouping reaches at least 5 supporting games. This may reduce a build to 5, 4, or 3 core items.
Build cards display a N-slot core badge when slots were reduced, or a ⚠ below threshold warning if even the most common combination had fewer than 5 games.
Item Tooltips
Hover any item icon to see its name, individual win rate, and game count at that time bucket. The ~Xm badge in the corner shows the time snapshot (in minutes) from the API where this item was most commonly recorded.
